An endpoint declares its types, who may call it, whether it runs in a transaction and which errors it returns. That one declaration drives routing, validation, the OpenAPI document and the optional rules that `hinoki check` runs against your source — so the architecture of the app is something you can verify, not something you remember.

The pieces are plain Python, one per file. Here is the task tracker from the repository's [examples](https://github.com/caspel26/hinoki/tree/main/examples/tracker), abridged:

```python
# security.py: who may call. One reusable policy.
member_only = Access(auth=MemberTokens(), permissions=[USE])

# schemas.py: what crosses the boundary. A model column reaches a client only through a Schema.
class TaskIn(Schema):
    title: Annotated[str, Field(min_length=1, max_length=120)]

@derive(Task, exclude=("owner_id",))
class TaskOut(Schema): ...

# api.py: the endpoint. Access and transactions are stated once for the whole group.
tasks = RouteGroup("/tasks", access=member_only, atomic=True)

@tasks.post("/", status=201)
async def create_task(data: TaskIn, caller: Caller[Member]) -> TaskOut:
    return await operations.create_task(caller.user.id, data)
```

Routing, input validation, the OpenAPI document and the docs come from those declarations. Add a handler without an access policy and `hinoki check` reports it with the file, the line and the rule (sample from the [Rules guide](https://hinoki.caspel.dev/dev/rules/)):

```text
tests/projects/rulesapp.py:12: HNK-ACC-001 [violated] POST /items (create) declares no access policy
```

- **Declared** — access, transactions and errors are options of the decorator or defaults of a route group, and they land in OpenAPI.
- **Checked** — eleven built-in rules (access, permissions, transactions, exposed fields, imports and more); a new project turns on eight. Every finding has a file, a line and a fix.
- **Strict** — input is validated without coercion and unknown fields are refused. A response carries only what its `Schema` names.
- **Explicit** — nothing connects at import. Tables change only through SQL migration files you review and apply.
- **Rust core** — path matching, schema validation, cryptography and database execution run in a compiled extension, and apps run on Kiso, Hinoki's own Rust HTTP server (Granian is optional). Handlers stay Python, sync or async.
- **Included** — typed schemas and settings, generated OpenAPI, an ORM for PostgreSQL, SQLite, MySQL and MariaDB, generated CRUD, test clients, MCP tools and an optional admin.

<summary><b>goninja</b> · features, install, demo</summary>

<br>

Code-first CRUD REST APIs for Go, generated from annotated structs.

- 🧬 Annotate a struct, run one command, get real `.go` files you commit
- 🚫 Zero reflection on the request path — a bad tag fails `go build`, not production
- 🧷 Output types are separate structs, so a field can't leak into a response
- 🪢 No N+1 by construction — `list` never preloads, `retrieve` preloads what it carries
- 🔎 Filters, range queries, ordering and limit/offset pagination
- 🔐 `Authenticator` objects, per-route policy, reflected into the OpenAPI security schemes
- 📘 OpenAPI 3.0 with Swagger UI and ReDoc embedded — no external CDN
- 🐹 Plain `net/http` + GORM, no custom router

[Documentation](https://goninja.dev) · [Changelog](https://goninja.dev/docs/changelog/) · [GitHub](https://github.com/caspel26/goninja)

<summary><b>shimwire</b> · features, install, demo</summary>

<br>

One CLI for both sides of an API you don't fully control yet — mocks the parts that aren't built, and tests the parts that are, from a single OpenAPI/Swagger spec.

- 🔀 Spec-driven mock server and test collections, from one shared engine
- 📁 Git-native collections — plain TOML, reviewable in a normal PR diff
- 🎭 Schema-aware fake data, not just random junk
- 🎯 Overrides for status/latency/exact-body edge-case testing
- 🖱️ Guided interactive menu, or full CI-friendly flags
- 📊 HTML reports and `--fail-on-error` for CI
- 🤖 MCP server — an AI agent can inspect a spec, scaffold a project, and verify it actually works, without knowing shimwire's flags
